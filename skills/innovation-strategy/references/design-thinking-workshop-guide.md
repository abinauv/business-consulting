# Design Thinking Workshop Guide

## Overview and When to Use

### Design Thinking vs. Other Methods

| Method | Best For | Duration | Output |
|--------|---------|:--------:|--------|
| **Design thinking** | Ambiguous problems, customer-centric innovation, complex systems | 1–5 days | Customer insights, solution concepts, testable prototypes |
| **Lean startup** | Testing business models, validating demand | 2–8 weeks (sprints) | Validated/invalidated hypotheses, MVPs |
| **Traditional R&D** | Technical innovation, deep research | Months–years | Specifications, patents, technical solutions |
| **Agile** | Software development, iterative building | 2-week sprints | Working software increments |

**Use design thinking when:**
- The problem is unclear or poorly defined
- Solutions require deep customer empathy
- Cross-functional collaboration is needed
- Creative/divergent thinking is required
- You need to quickly explore many options before committing

## Workshop Planning Checklist

### Pre-Workshop

| Item | Details | Lead Time |
|------|---------|:---------:|
| **Define challenge** | Clear "How Might We" question or problem area | 2 weeks |
| **Select participants** | 6–12 people, cross-functional, include customer-facing roles | 2 weeks |
| **Arrange space** | Large room, movable furniture, wall space for posting | 1 week |
| **Materials** | Post-its (5 colors), markers (thick tip), large paper, dots for voting, timer | 3 days |
| **Customer research** | Share pre-read with customer interview summaries, data, insights | 1 week |
| **Invite customers** | If possible, have 2–3 customers attend for empathy phase | 2 weeks |
| **Set rules** | "Yes, and..." culture, no hierarchy, defer judgment, quantity over quality | Day of |
| **Assign facilitator** | Experienced facilitator who won't participate in ideation | 2 weeks |

## Phase 1: Empathize (60–90 minutes)

### Objective
Develop deep understanding of the customer's experience, needs, emotions, and context.

### Exercise 1: Empathy Map (30 minutes)

Draw a large empathy map on the wall for each customer segment:

```
         ┌──────────────────────────────┐
         │        THINKS & FEELS        │
         │  (worries, aspirations,      │
         │   emotions, internal state)  │
    ┌────┼──────────────────────────────┼────┐
    │    │                              │    │
    │ S  │                              │ H  │
    │ E  │                              │ E  │
    │ E  │      [CUSTOMER NAME]         │ A  │
    │ S  │                              │ R  │
    │    │                              │ S  │
    │    │                              │    │
    ├────┼──────────────────────────────┼────┤
         │         SAYS & DOES          │
         │  (actions, behaviors,        │
         │   observable activities)     │
         └──────────────────────────────┘
         ┌──────────────────────────────┐
         │      PAINS         GAINS     │
         │  (frustrations)  (desires)   │
         └──────────────────────────────┘
```

**Process:**
1. Each person writes observations on post-its (1 idea per post-it, thick marker)
2. Place on the empathy map in the relevant quadrant
3. Group discusses patterns and surprises
4. Circle the 3 most important insights

### Exercise 2: Customer Interview (30 minutes, if customers present)

Live interview with 1–2 customers while the team observes and takes notes.

**Interview structure:**
- 5 min: Context ("Tell us about your role and typical day")
- 10 min: Problem exploration ("Walk us through how you handle [problem area]")
- 10 min: Emotions and impact ("What frustrates you most? What would ideal look like?")
- 5 min: Wrap up ("Anything else we should know?")

**Team members:** Listen only, write observations on post-its. No selling or defending.

### Exercise 3: Journey Snippet (30 minutes)

Map a specific episode in the customer's journey:

| Step | Action | Emotion | Pain Point | Opportunity |
|:----:|--------|:-------:|-----------|-------------|
| 1 | | 😊/😐/😠 | | |
| 2 | | | | |
| 3 | | | | |

## Phase 2: Define (30–45 minutes)

### Objective
Synthesize empathy findings into a clear problem statement.

### Exercise 4: Insight Clustering (15 minutes)

1. Post all empathy observations on the wall
2. Silently group related post-its into clusters (affinity mapping)
3. Name each cluster with a theme statement
4. Vote on the top 3 most important themes (3 dots per person)

### Exercise 5: Problem Statement — Point of View (15 minutes)

Create a Point of View (POV) statement:

```
[USER] needs to [USER'S NEED] because [SURPRISING INSIGHT]
```

**Examples:**
- "A busy operations manager needs to get real-time visibility into factory performance because they currently spend 60% of their week compiling manual reports instead of making decisions."
- "A first-time buyer needs to feel confident in their purchase because they're overwhelmed by options and afraid of making an expensive mistake."

### Exercise 6: How Might We (HMW) Questions (15 minutes)

Convert the POV into 5–8 "How Might We" questions:

**Rules for good HMW questions:**
- Broad enough to allow creative solutions
- Narrow enough to be actionable
- Start with "How might we..." (not "How can we..." — "might" implies possibility)

**Example HMWs:**
- "How might we give operations managers real-time visibility without requiring manual data entry?"
- "How might we help first-time buyers feel confident without overwhelming them with information?"
- "How might we turn the frustration of [pain point] into a moment of delight?"

**Vote:** Each person gets 3 dots. Top 2–3 HMW questions move to ideation.

## Phase 3: Ideate (60–90 minutes)

### Objective
Generate as many solutions as possible, then converge on the best ideas.

### Brainstorming Rules (Post on the wall)

1. **Defer judgment** — No "but" or "that won't work" during brainstorming
2. **Encourage wild ideas** — They can be refined later
3. **Build on others' ideas** — "Yes, and..."
4. **Stay focused** — One HMW question at a time
5. **One conversation at a time** — Listen, then add
6. **Be visual** — Sketch ideas, don't just write words
7. **Go for quantity** — Aim for 50+ ideas in 15 minutes

### Exercise 7: Crazy 8s (8 minutes)

1. Fold a sheet of paper into 8 panels
2. Set timer for 8 minutes (1 minute per panel)
3. Each person sketches 8 different solution concepts
4. Share with the group (30 seconds per person)

### Exercise 8: SCAMPER Ideation (15 minutes)

Use SCAMPER prompts to generate ideas:

| Prompt | Question | Example |
|--------|---------|---------|
| **S** — Substitute | What can we substitute? | Replace human review with AI |
| **C** — Combine | What can we combine? | Combine onboarding with training |
| **A** — Adapt | What can we adapt from elsewhere? | Adapt Netflix recommendations for our product |
| **M** — Modify | What can we enlarge, minimize, or change? | Make the process 10x faster |
| **P** — Put to another use | Can we use this differently? | Use support data for product insights |
| **E** — Eliminate | What can we remove? | Eliminate the approval step |
| **R** — Reverse/Rearrange | What if we flip the sequence? | Let customers set their own price |

### Exercise 9: Dot Voting and Selection (15 minutes)

1. Post all ideas on the wall
2. Each person gets 5 dots (green = "I like this", red = "This is novel/risky")
3. Count votes → identify top 5–8 ideas
4. Discuss: Which ideas to prototype? (Consider impact, feasibility, novelty)
5. Select 2–3 ideas to prototype

## Phase 4: Prototype (60–120 minutes)

### Objective
Create quick, low-fidelity prototypes to test with customers.

### Prototype Types

| Type | Effort | Best For | Tools |
|------|:------:|---------|-------|
| **Paper sketch** | 10 min | Visual concepts, UI layouts | Paper, markers |
| **Storyboard** | 20 min | Customer journey, service concepts | 6-panel template |
| **Role play** | 15 min | Service interactions, processes | People, props |
| **Landing page** | 1–2 hours | Testing demand, messaging | Carrd, Webflow, Figma |
| **Wizard of Oz** | 2–4 hours | Testing complex interactions (human behind the curtain) | Manual process mimicking automated one |
| **Clickable wireframe** | 2–4 hours | Testing digital product concepts | Figma, Balsamiq |
| **Video** | 1–2 hours | Explaining complex concepts, vision | Smartphone, simple editing |

### Storyboard Template

| Panel 1: Context | Panel 2: Trigger | Panel 3: Action |
|:---:|:---:|:---:|
| Who is the user? What's their situation? | What triggers them to use our solution? | What do they do? How do they interact? |
| [Sketch] | [Sketch] | [Sketch] |

| Panel 4: Reaction | Panel 5: Outcome | Panel 6: Impact |
|:---:|:---:|:---:|
| How do they feel? What's their reaction? | What's the immediate result? | How has their life/work improved? |
| [Sketch] | [Sketch] | [Sketch] |

### Prototyping Tips

- **It should take <60 minutes** — If it takes longer, you're over-building
- **Make it just real enough to get feedback** — Not polished, not production-ready
- **Make it throwaway** — Don't fall in love with your prototype
- **Test one concept per prototype** — Don't cram multiple ideas together
- **Label it "prototype" or "concept"** — So testers know it's not finished

## Phase 5: Test (45–60 minutes)

### Objective
Get customer feedback on prototypes to validate or invalidate hypotheses.

### Testing Protocol

1. **Set up** (2 min): "We're testing an early concept. We want your honest feedback. There are no right or wrong answers. The prototype is rough on purpose — we want to learn before we build."
2. **Show the prototype** (1 min): Brief explanation of what it is
3. **Let them interact** (5–10 min): Watch how they use/react to it. Don't explain or help unless they're completely stuck
4. **Ask questions** (5–10 min):
   - "What was your first reaction?"
   - "What did you like? What confused you?"
   - "Would you use this? Why or why not?"
   - "What would make this better?"
   - "How does this compare to what you do today?"
5. **Document** (2 min): Capture key observations immediately after

### Feedback Capture Grid

| What Worked | What Didn't Work |
|-------------|-----------------|
| [Things they liked, intuitive parts, positive reactions] | [Confusion, frustration, negative reactions, missing elements] |

| Questions Raised | New Ideas |
|-----------------|-----------|
| [Things we need to investigate further] | [Suggestions from testers, improvements, pivots] |

### Iteration Planning

After testing, decide for each prototype:

| Decision | When | Next Step |
|----------|------|----------|
| **Iterate** | Feedback is positive but improvements needed | Refine prototype, test again |
| **Pivot** | Core concept didn't resonate but learned something valuable | Redesign using learnings, new HMW question |
| **Proceed** | Strong positive signal, clear demand | Move to business case (Gate 3) |
| **Kill** | No interest, fundamental flaw | Stop, redirect resources |

## Facilitation Tips

### Energy Management

| Time | Energy Level | Facilitator Action |
|------|:-----------:|-------------------|
| Start of day | Medium → High | Warm-up exercise, energizing music, set enthusiastic tone |
| Mid-morning | High | Ride the wave, most divergent thinking here |
| Post-lunch | Low | Energizer activity (1 min), hands-on prototyping (keeps energy up) |
| Late afternoon | Declining | Keep activities short, varied; timer creates urgency |

### Dealing with Common Challenges

| Challenge | Intervention |
|-----------|-------------|
| **One person dominates** | "Let's hear from someone who hasn't spoken yet." Use silent brainstorming (post-its). |
| **Group goes off-topic** | "That's interesting — let's capture it in the parking lot and come back to our HMW." |
| **Skeptic/cynic** | Acknowledge their expertise privately; give them the "devil's advocate" role (constructive). |
| **Analysis paralysis** | Set a timer. "We need to decide in 3 minutes. We can always iterate." |
| **Groupthink** | "Before we discuss, everyone write your top idea silently." Compare. |
| **Energy drops** | Stand up, change groups, do a 1-minute energizer, or take a 5-min break. |
| **Ideas too safe** | "What would [Apple/Tesla/a competitor] do?" or "What if money was no object?" |
